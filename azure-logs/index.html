لاگ‌های منابع Azure Monitor را مستقیم از حساب ذخیره‌سازی خودتان بخوانید، دسته‌بندی‌شده بر اساس منبع. مرورگر مستقیم با Azure حرف می‌زند و هیچ چیز از سرور ما رد نمی‌شود.

پیش از شروع: CORS و توکن SAS
  1. اجازه‌ی CORS. مرورگر فقط وقتی می‌تواند از حساب ذخیره‌سازی بخواند که سرویس Blob آن، نشانی این صفحه را مجاز کرده باشد. در پورتال Azure: حساب ذخیره‌سازی ← Settings ← Resource sharing (CORS) ← زبانه‌ی Blob service، یک قانون بیفزایید:
    • مبدأهای مجاز (Allowed origins):
    • روش‌های مجاز (Allowed methods): GET و OPTIONS
    • سرآیندها (Allowed / Exposed headers): *، و Max age: 3600
    یا با Azure CLI: 
    
        اگر فایروال حساب روشن است، نشانی IP شما هم باید مجاز باشد. صفحه‌ای که از روی دیسک (file://) باز شود مبدأ ندارد؛ از نشانی وب یا یک سرور محلی استفاده کنید.
      
    2. 
      
  2. 
        توکن SAS فقط‌خواندنی. حساب ذخیره‌سازی ← Security + networking ← Shared access signature:
        
      
          
    • سرویس: Blob؛ نوع منابع: Service، Container، Object
      • 
          
    • دسترسی‌ها: فقط Read و List؛ پروتکل: HTTPS only؛ انقضای کوتاه
      • 
        
    
        بدون نوع Service فهرست کانتینرها در دسترس نیست و نام کانتینر (مثل insights-logs-…) را باید خودتان بنویسید. توکن SAS یک کانتینر با Read و List هم کار می‌کند.
      
    3. 
      
  3. 
        توکن کجا می‌رود؟ فقط در حافظه‌ی همین صفحه می‌ماند: ذخیره نمی‌شود، در نشانی صفحه نمی‌آید و فقط به <account>.blob.core.windows.net فرستاده می‌شود. با بستن یا بازخوانی صفحه فراموش می‌شود.
      
    4. 
    

    
    
      
  1. 
        Allow CORS. The browser can only read the storage account if its Blob service allows this page's origin. In the Azure portal: storage account → Settings → Resource sharing (CORS) → the Blob service tab, add a rule:
        
      
          
    • Allowed origins: 
      • 
          
    • Allowed methods: GET and OPTIONS
      • 
          
    • Allowed headers and Exposed headers: *; Max age: 3600
      • 
        
    
        Or with the Azure CLI:
        
    
        If the account's firewall is on, your IP address must be allowed too. A page opened from disk (file://) has no origin; use the website or a local server.
      
    2. 
      
  2. 
        A read-only SAS token. Storage account → Security + networking → Shared access signature:
        
      
          
    • Allowed services: Blob; resource types: Service, Container, Object
      • 
          
    • Permissions: only Read and List; protocols: HTTPS only; a short expiry
      • 
        
    
        Without the Service type the container list is not available, so type the container name (such as insights-logs-…) yourself. A container SAS with Read and List works too.
      
    3. 
      
  3. 
        Where does the token go? It stays in this page's memory only: it is not saved, never appears in the address bar, and is sent only to <account>.blob.core.windows.net. Closing or reloading the page forgets it.
